# Project brief: Google Ads management website

Read this whole file before writing code. It is the approved plan; follow it unless the owner says otherwise.

## What we're building

A small, fast, static, US-facing marketing site that sells one service:
**Ads Upkeep — Google Ads management at $179/month, month to month.**
Its only job is to get small-business owners to **book a free 15-minute review**.
It also hosts personalized prospect pages used in cold outreach.

- Audience: owners of single-location US service businesses already running Google Ads (~$500–$3,000/month spend). Mostly on phones.
- Brand: **working name** until the owner picks one. Keep it in `src/config/site.ts` only, so renaming is one edit. Use `Working Name` as the placeholder.
- **Never** show a founder or personal name anywhere: pages, metadata, structured data, Open Graph images, legal pages, alt text, comments.

## Stack (do not swap without asking)

- Astro 7, static output, no SSR adapter.
- Hosting: Cloudflare Workers static assets (`wrangler.jsonc` with `assets.directory: "./dist"`).
- Booking: Cal.com link (placeholder URL in `site.ts`).
- Forms: Tally embed (placeholder form ID in `site.ts`).
- Analytics: Cloudflare Web Analytics (cookie-free; token placeholder in `site.ts`).
- No JavaScript framework on pages. Only tiny inline scripts where unavoidable (mobile menu can use `<details>`).

- Header (every page): wordmark, nav (How it works, Pricing, Free review, FAQ), booking button. Phones: one menu button.
- Footer: About, Contact, Privacy, Terms, Service terms, postal address, "Independent. Not affiliated with or endorsed by Google."
- Every selling page ends with the same button: **Book a 15-minute review**. Secondary action only: **Get a written review**.

### The offer (single source: `src/data/offer.yaml`)

Included: month-1 clean-up (search terms, negatives, assets, check that call/form tracking fires); one ~90-minute optimization pass per month; weekly 10-minute check (pacing, disapprovals, tracking); one-page monthly report in plain English; up to 2 change requests/month done within 2 business days; email support, reply within 1 business day; client owns the account and pays Google directly.
Not included: more than 2 campaigns; Performance Max, Shopping, Display, YouTube; landing-page builds; call-tracking platform setup; weekly calls; Meta, LSA, SEO; multi-location; any guarantee of leads.
Promises: no contract, no setup fee, cancel by email; first-month refund if not worth it; the account stays theirs (manager link, removable in one click).

## URL rules

- Lowercase, hyphens, trailing slash (`trailingSlash: 'always'`, `build.format: 'directory'`). Apex domain only; `www` redirects.
- Prospect pages at the root: `/<business-slug>/`, generated by `src/pages/[slug].astro` from `src/data/prospects.csv` (columns as in `reference/landing-page-kit/leads_template.csv`).
- Reserved slugs (build must fail if a prospect slug matches): all site page slugs plus `about blog guides industries resources api assets fonts admin thanks book review legal`. On duplicate business names, append the city.
- Prospect pages: `noindex` meta + `X-Robots-Tag` header via `public/_headers`, excluded from `sitemap.xml`, never linked.
- Rows with `fit=N`, `status` in {dnc, unsubscribed, expired} are skipped. Pages stay up ≥30 days.
- Booking links carry `utm_content=<slug>` (prospects) or `utm_content=<page>` (site pages).

## Design standard ("service log") — fresh identity

Concept: Google Ads management as routine, recorded upkeep, like a mechanic's service logbook. Show the work, not hype. One bold element per page (the service log, or the price on Pricing). Paperwork, not software. Legible on a phone.

Colors (CSS variables in `src/styles/tokens.css`):

| Token | Hex | Use |
| --- | --- | --- |
| `--paper` | `#F1F3EE` | Page background |
| `--ink` (ledger green) | `#1E3B32` | Headings, body text, button borders, focus ring (10.9:1 on paper) |
| `--moss` | `#5A6B62` | Secondary text, log column labels (5.1:1) |
| `--rule` | `#C8D2CA` | Lines only, never text |
| `--signal` | `#F7893E` | Booking button fill only (ledger-green text on it: 5.0:1). Never text on paper |
| `--stamp` | `#B5480F` | "Checked" stamp, active nav underline, error text (4.8:1) |
| `--manila` | `#F3E3B5` | Paper-tag notes ("What we can't see", "Example") |
| `--white` | `#FFFFFF` | Service log and form surfaces |

Type: **Archivo** variable (wdth + wght axes), self-hosted, one Latin-subset woff2, preloaded. Headings use the wide width; body normal width. Tabular numerals for prices, dates, log.

Layout: 12 columns, 1120px max, 24px gutters, 16px side margins on phones, left-aligned, prose ≤68ch. Spacing scale 4, 8, 12, 16, 24, 32, 48, 64, 96, 128. Sections 96px apart (64 on phones), separated by one ruled line. Corners 4px (buttons, inputs), 6px (log surface). No shadows, no pills.

Components:
- **ServiceLog** (signature): white surface, 1.5px ink top rule; columns Date / What was checked / What changed; rule lines between rows; small outlined "Checked" stamp in `--stamp`. Always labelled "Example" on the site; never shows numbers that look like client results. Same format later used for monthly reports and prospect-page observations.
- **BookingButton**: `--signal` fill, `--ink` text 17px/600, 1.5px `--ink` border, min-height 48px, label always "Book a 15-minute review", no arrow icons.
- **SecondaryButton**: `--ink` outline + text. Only "Get a written review".
- **TextLink**: ink, 1px underline, 3px offset; thicker on hover.
- **PriceBlock**, **ScopeList** (✓ included in ink / – excluded in moss, separate column), **Steps** (numbered 1–4; it's a real sequence), **PaperTag** (manila panel, no icon), **Faq** (native details/summary, +/− marker), **TallyForm**, **Header**, **Footer**.
- Forms: label above, 17px inputs, 1px rule border → 1.5px ink on focus, errors in `--stamp` with written explanation.

Imagery and motion: no stock photos, no photos of people, no Google logos. Icons: Lucide outline, 1.5px, ink, only where meaningful. No load animations; only state changes animate; respect `prefers-reduced-motion`.

Not allowed: cream/terracotta palettes, ALL-CAPS eyebrow labels, monospace data labels, arrows on buttons, grids of identical shadowed cards, gradient washes, fake counters (any number that is not in the allowed claims above), stock handshake photos, "10x" language.

## Copy and honesty rules (hard rules)

Voice: plain US English, sentence case, short sentences, numbers over adjectives. Second person about their account. "We" is fine but never imply a team, office or capacity that doesn't exist.

Allowed experience claims (owner-confirmed), written as "one specialist" or "the specialist behind Ads Mechanic":
- Hands-on work in 2,000+ small-business Google Ads accounts across the US and Canada
  (150–200 new businesses every quarter for 3 years; 12 quarters x 150–200 = 1,800–2,400).
- 3 years of full-time, hands-on Google Ads work: account setup and structure, keyword research,
  negative keywords, ad copy and assets, bidding and budgets, conversion tracking, and advice to owners.
- Breadth: almost every kind of small business, including schools, driving and chef schools,
  wellness and mental-health course creators, cobblers, airport taxi services, trades,
  local services and e-commerce.
- Campaign types: Search, Performance Max, Demand Gen, Display, Shopping, Video.
  Conversion tracking with Google Tag Manager and GA4.
- Google Skillshop certifications: list only ones that are currently valid (owner fills in).

Wording rules for the numbers:
- Say "worked hands-on in" or "worked inside" 2,000+ accounts. Never "managed 2,000+ clients": most were set-up and optimization work, not ongoing monthly management.
- Never multiply or round up further (no "thousands", "3,000+", "10,000 campaigns").
- Never add results, spend totals, ROAS or lead numbers.
- The figure lives in `site.experience.accounts` in `src/config/site.ts`; pages read it from there.

Never write: employer names; "ex-Google", "inside Google", "Google Partner"; sales-target percentages; client names, logos, results or testimonials; guarantees of leads or results; invented numbers of any kind; any personal name.

Proof comes from: the free review, published price and scope, service terms, first-month refund, "you keep your account", a sample report labelled "Sample", an honest FAQ.

Add a build-time check (`scripts/check-content.mjs`) that fails on: personal-name placeholders left in output, prospect slugs in the reserved list, missing required prospect fields. It warns on "audit", "wasting", "losing", "guarantee", and percentages in prospect observations.

## Quality floor (definition of done for each page)

- WCAG 2.2 AA: 4.5:1 body text, visible focus everywhere, 44px tap targets, skip link, labelled fields, ordered headings.
- No JS framework; one font file; first load < 200 KB excluding Cal.com/Tally embeds; LCP < 2s on mid-range mobile; CLS < 0.05; Lighthouse performance ≥ 95.
- Unique title/description per site page; `sitemap.xml` (no prospects); `robots.txt`; structured data `Organization`, `Service` ($179 offer), `FAQPage` — never `Person`.
- `public/_headers`: security headers + CSP allowing only Cal.com, Tally, Cloudflare Web Analytics and the visit-logger URL; noindex on prospect paths and `/thanks/`.
